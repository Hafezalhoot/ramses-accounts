# دليل تجربة G2V — النسخ المشفر قبل الترقية (TEST ONLY)

**نظام حسابات مستشفى رمسيس · V8.1E-G2V · 31 أكتوبر 2026**

هذه حزمة تطوير تجريبية، **غير مصرح لها بالتشغيل المالي الحقيقي أو على بيانات المرضى**. لا تغير قاعدة المستشفى القائمة ولا تنشرها على أجهزة المستشفى قبل موافقة المالية والإدارة الطبية وتقنية المعلومات وتجربة تشغيل موازية.

## الجديد

عند فتح قاعدة قديمة تحتاج ترقية، يصدر النظام قبل أي تغييرات في مخططها ملف تراجع متسقًا باسم `before_*.rbe` مشفرًا بتقنية AES-256-GCM. ويعيد فكّه إلى نسخة اختبار منفصلة ويتحقق من سلامة SQLite والعلاقات قبل إتاحة الترقية. كلمة المرور غير موجودة في الكود ولا في ملف ZIP. إذا غابت أو كان ملف المفتاح مكشوف الصلاحيات، **ترفض الترقية قبل تنفيذ DDL**. قاعدة متوافقة مسبقًا لا تحتاج إنشاء نسخة جديدة عند كل إعادة تشغيل.

تم أيضًا إيقاف حفظ نسخة SQLite نصية دائمة أثناء تحويل جدول الورديات القديم. قد يوجد ملف SQLite مؤقت في مجلد خاص أثناء التشفير والتحقق؛ من الضروري استخدام قرص مشفر حتى أثناء التجربة المؤسسية. النسخ المحلية لا تعني أن نسخة ثانية موجودة خارج الجهاز.

## طريقة التشغيل على قاعدة تجريبية فقط

1. افصل أي اتصال بقاعدة مستشفى حقيقية. جهز قاعدة اختبار `RAMSES_DB_PATH` منفصلة.
2. ضع كلمة مرور قوية فريدة (16 بايت على الأقل؛ ينصح بأطول) في ملف **مملوك للمستخدم وحده** بصلاحيات `0600` داخل مجلد خاص `0700`. مثال لإنشاء ملف من دون إدخال كلمة المرور في سجل أوامر shell:

```bash
mkdir -p "$HOME/ramses-test-secrets"
chmod 700 "$HOME/ramses-test-secrets"
python3 - <<'PY'
import os
from getpass import getpass
from pathlib import Path
p = Path.home() / 'ramses-test-secrets' / 'backup-passphrase'
p.write_bytes(getpass('New synthetic backup passphrase: ').encode('utf-8'))
os.chmod(p, 0o600)
PY
```

3. على نسخة اختبار معزولة، من مجلد المشروع وبعد تثبيت `requirements.txt`، فعّل المتغيرات:

```bash
mkdir -p "$HOME/ramses-test-db"
chmod 700 "$HOME/ramses-test-db"
export RAMSES_DB_PATH="$HOME/ramses-test-db/ramses.sqlite3"
export RAMSES_BACKUP_PASSPHRASE_FILE="$HOME/ramses-test-secrets/backup-passphrase"
python3 bootstrap.py
```

عند عدم وجود قاعدة قديمة، يلزم تعريف `RAMSES_ADMIN_USER` و`RAMSES_ADMIN_PASSWORD` بطريقة آمنة لإنشاء أول مستخدم؛ لا تستخدم كلمة مرور حقيقية في أمثلة أو سجلات مشتركة.

4. إذا كانت قاعدة اختبار قديمة، ستجد ملف `.rbe` في أحد مجلدات `pre_*_backups` بجوار قاعدة البيانات، بعد التحقق الكامل. نفذ اختبار استعادة **إلى مسار جديد لا يوجد**:

```bash
python3 scripts/secure_backup.py verify --input /path/to/before_upgrade.rbe
python3 scripts/secure_backup.py restore --input /path/to/before_upgrade.rbe --output-file /path/to/isolated-restore.sqlite3
```

النسخة المستعادة من إصدار أقدم **متعمد أن يكون مخططها قديمًا**؛ لا تفتحها مباشرة في الخدمة المالية دون خطة ترقية معتمدة. الاستعادة لا تستبدل قاعدة بيانات موجودة.

## تنبيهات تشغيل أساسية

- يجب الاحتفاظ بملفات `.rbe` وأسرار فكّها في أماكن منفصلة ذات صلاحيات محدودة، مع خطة تدوير مفاتيح وحفظ خارجي ومراجعة استعادة على جهاز آخر؛ **لم يُثبت ذلك على أجهزة رمسيس**.
- أي ملفات قديمة من نوع `pre_*_backups/*.sqlite3` التي أنشأتها الإصدارات السابقة لن تُحذف تلقائيًا؛ تحتاج جردًا وتقييم احتفاظ ثم إجراء إتلاف آمن بمعرفة تقنية المعلومات وبعد استعادة مشفرة ناجحة.
- إذا فشلت الترقية بسبب فقد الملف أو عدم تطابق المفتاح، لا تعطل الحماية ولا تعدل صلاحيات قاعدة البيانات عشوائيًا. استعن بالمسؤول عن النسخ والمفاتيح.
- قد يتطلب بدء التشغيل الأول للموقع إعداد خدمة محلية وأسماء مستخدمين. لا تفتح `START_Ramses_Mac.command` على بيانات حقيقية قبل UAT.

**المخاطر الباقية:** إثبات طبي مستقل لتنفيذ الخدمات، مصفوفة شاملة لصلاحيات العرض والتقارير، اعتماد إثبات الصرف، الموردون والمخازن المتعددة والتأمين والأطباء، اختبار V8.0 التاريخي، والتعافي خارج الموقع. **قرار الإنتاج: NO-GO.**
