# دليل تجربة نظام رمسيس V8.1E-G3B — مصدر إثبات ذي بصمة، نسخة اختبار فقط

**NO-GO:** هذه ليست نسخة مستشفى معتمدة، ولا تصلح لسجلات مرضى حقيقية. جرّب بملفات PDF/JPG/PNG وهمية دون أسماء أو تشخيصات أو صور أشخاص حقيقية. لم يتم اعتماد توقيع طبي إلكتروني أو الربط مع نظام سجلات طبية.

1. استخرج ZIP في مجلد نظيف. اقرأ `README_G3A_AR.md` لتجهيز بيئة Python وحساب `clinician` والمراجعة اليدوية للقسم؛ اتبع `README_G2V_AR.md` لتجهيز مفتاح نسخ التراجع المشفر خارج السورس، بصلاحية ملف `0600`.
2. شغّل خادم الحسابات المحلي بالطريقة الموجودة في `README_AR.md`، أو على Mac افتح `START_Ramses_Mac.command`. استخدم **قاعدة اختبار جديدة فقط**، ولا توصل التطبيق بأي خادم إنتاج أو Google Sheets حقيقية.
3. المالك يُنشئ حسابًا طبيًا، ويسجل مراجعة هوية يدوية تجريبية ويمنح التفويض للقسم، ثم يفعّل شرط الإثبات الطبي المستقل. إن رغب في اشتراط مصدر ملف، يستخدم «الإدارة ← إلزام بصمة مصدر طبي» ويؤكد كلمة المرور. القرار **دائم في نسخة التطبيق**؛ لا تُفعّله قبل اختبار أثره على الخدمات القديمة غير المفوترة.
4. المالك يفتح حالة طبية وخدمة **وهمية** ويطلب تنفيذها. الحساب الطبي يرى طابور القسم المسموح فقط. عند إثبات الخدمة يمكن كتابة مرجع وهمي وإرفاق ملف PDF/JPEG/PNG وهمي بحجم لا يتجاوز 6 ميجابايت؛ يصبح الملف إلزاميًا للقسم المفعّل فقط.
5. ينتج API بصمة SHA-256 وحجم ونوع الملف في إثبات واحد غير قابل للتعديل من التطبيق؛ **لا يحفظ اسم الملف أو محتواه بقاعدة الحسابات**. احفظ الأصل بالاسم المناسب في نظام السجلات الطبية المفوض خارج هذا البرنامج. للتحقق لاحقًا أرسل الملف نفسه إلى `POST /api/billing/clinical/lines/{id}/verify-document` من حساب طبي مفوض؛ النتيجة `matches: true` للملف نفسه و`false` للمختلف.
6. جرّب رفض محاولة إثبات من حساب `viewer` أو الكاشير أو حساب طبي أُلغي تفويضه، ورفض فاتورة جديدة لخدمة قسم مشروط قبل الإثبات. افحص شاشة الواجهة على 320/375/1440 بكسل.
7. ترقية قاعدة G3A القديمة **تستلزم مفتاح نسخة التراجع المشفرة قبل أي DDL**. اختبر الترقية على نسخة وهمية مستقلة؛ لا تترجم سجلات المصدر القديم إلى بصمات جديدة، ولا تتجاوز معوقات الإقفال أو الآثار المحاسبية.
