# دليل تجربة حسابات رمسيس G3A — TEST ONLY

**تحذير:** النسخة غير معتمدة للمستشفى أو المرضى أو الفواتير الحقيقية؛ لا تستخدم قاعدة G2Z التشغيلية أو صورًا حقيقية لهويات الأطباء. التجربة حصريًا ببيانات وهمية وعلى جهاز معزول.

1. فك الحزمة ZIP داخل مجلد جديد. اقرأ `README_G2V_AR.md` لتجهيز Python ومفتاح النسخ المشفرة؛ لا تضع كلمة مرور النسخة في Git أو السورس.
2. أنشئ قاعدة SQLite اختبار جديدة؛ شغّل `START_Ramses_Mac.command` أو خادم FastAPI وفق `README_AR.md`. استخدم كلمة مرور مالك تجريبي قوية.
3. من **الإدارة ← المستخدمون** أنشئ حسابًا منفصلًا بدور **موثّق خدمات طبي — اختبار**، لا بدور مشاهد التقارير.
4. من **الإدارة ← مراجعة الهوية المهنية** اختر الحساب الطبي؛ أدخل اسمًا ومرجع تسجيل وملاحظة **اصطناعية** وأعِد كلمة مرور المالك؛ اختر «مراجعة مكتملة». هذا مجرد اعتماد إداري يدوي **ليس تحققًا رسميًا من ترخيص طبي**.
5. من **التفويض الطبي** اختر الحساب الطبي والقسم ومنح التفويض؛ لا يمكن منح الدور الطبي لمشاهد أو محاسب. فعّل سياسة القسم **داخل قاعدة الاختبار فقط**؛ لا يمكن إطفاؤها مباشرة.
6. افتح حالة وهمية وخدمة وهمية من مسار الفوترة، ثم سجّل الدخول بالحساب الطبي. ستظهر له شاشة «إثبات الخدمات الطبي» فقط، بلا أي خزن أو مبالغ أو تقارير أو بيانات محاسبية. اكتب مرجعًا وهميًا مثل `SYN-CLINICAL-REF-2026`.
7. جرّب إصدار فاتورة قبل الإثبات وبعده بحساب الكاشير الوهمي؛ يجب أن يمنعها النظام قبل الإثبات إذا كانت سياسة القسم مفعّلة. جرّب سحب موافقة المراجعة الطبية أو تفويض القسم من حساب المالك، ثم حاول إثبات خدمة جديدة من جلسة الطبيب نفسها؛ يجب رفضها فورًا. اختبر أيضًا تغيير كلمة مرور الحساب الطبي أو تعطيله ثم إعادة تنشيطه؛ يجب إعادة مراجعة الهوية يدويًا قبل إثبات جديد.
8. انتبه: خدمة قديمة موثقة بواسطة `viewer` في G2Z وتنتظر الفوترة ستُمنع فاتورتها الجديدة في G3A حتى يُعتمد مسار تسوية تاريخية رسمي، دون تعديل إثباتها أو فواتير سبق إصدارها. لا تحاول تجاوز ذلك بتعديل SQLite يدويًا.
9. لا تسترجع نسخة G2Z الحقيقية إلى G3A. اختبار الترحيل يستخدم نسخة SQLite تاريخية **صناعية** مع أرشيف تراجع مشفر واختبار استعادة منفصل. لا تتم ترقية قاعدة عليها سياسة طبية مفعّلة إلا بعد إنشاء هوية جديدة معتمدة لكل قسم، لأن تفويضات المشاهد القديمة تُعلّق عمدًا.
