# G3K Ramses supplier bank settlement — scoped specification

G3J only authorizes supplier payment requests and posts nothing. G3K supports one bank cashbook voucher per approved G3J request, and a read-only bank-evidence reconciliation report. No bank transfer is initiated; this is only a book entry and the existing bank statement matching process remains the sole independently approved bank evidence.

Keep existing G3J permissions, Cairo CSS, and all earlier clinical/cashier rules. A specialized route creates one pending bank payment voucher linked atomically to an independently approved request and recorded evidence reference. Existing independent bank voucher approval posts **Dr 2200 supplier creditors / Cr bank fund**, once, using existing ledger and movement APIs; it must not re-post inventory or invoice accrual. Generic voucher input cannot choose this protected category. A bank voucher must not post if vendor deactivated, request status changes, link invalid, bank reviewer revoked, or attempted SQL shortcut. No overpayment and no generic reversal while a bank statement match is active (unmatch first); historical reversal without match is represented with an offsetting journal, not record deletion. Permissioned API exposes per-supplier scheduled, booked, actively matched, signed-bank-confirmed, and residual amounts, clearly labeled as scoped to the G3H inventory supplier invoices rather than every liability in account 2200. Month-close rules and immutable audit must remain safe. No live production changes and no bank connectivity.

UI: show linked voucher state and bank match evidence in existing inventory screen, plus minimal form for the authorized bank clerk. No passwords or font files bundled.
