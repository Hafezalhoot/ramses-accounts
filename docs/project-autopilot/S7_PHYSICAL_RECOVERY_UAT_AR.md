## بوابات القبول — لا تُعدّ أي حالة PASS دون دليل فعلي

- [ ] **مسار آمن:** استعملنا جهازًا مستقلًا فعليًا، ونسخة مشفرة من وسيط مصرّح، ومسار استعادة جديدًا، والقاعدة الأصلية لم تتغير.
- [ ] **الأرشيف:** تطابقت بصمة SHA256 بأصل مستقل، ونجحت AES-GCM وفحوص SQLite والقيد والمستندات.
- [ ] **التقرير:** صدر `recovery_report.json`، لكن حالة `physical_off_device_drill_verified:false` لم تُغيّر يدويًا.
- [ ] **التطبيق الفعلي:** اشتغل FastAPI/المتصفح على جهاز بديل بشبكة اختبار معتمدة وHTTPS حسب سياسة المؤسسة. اختبار ASGI المحلي وحده غير كافٍ.
- [ ] **الصلاحيات:** حساب تجريبي مخوّل دخل وخرج؛ غير المخوّل مُنع؛ لم تُستخدم كلمات مرور أو بيانات أشخاص حقيقيين في لقطات شاشة.
- [ ] **إعادة ربط التشغيل:** جرت مراجعة إعدادات الشبكة والخدمة والطابعة والموارد الخارجية ونسخها وفق سياسة IT، لا بمجرد نسخ SQLite.
- [ ] **حسابات النقد:** روجع دفتر وردية مغلقة وسجل تسليمها لخزنة داخلية ومستنداتها الأصلية/مرفقاتها.
- [ ] **الأستاذ العام:** تمت مطابقة ميزان المراجعة مع الخزنة والمرضى والموردين والشهر المطلوب باستخدام تقرير رسمي ومراجع مستقل.
- [ ] **الإثباتات:** فُتحت ملفات الإثباتات المضمنة داخل القاعدة، وتم التحقق من مكان حفظ المستندات/الملفات التي لا تحتفظ القاعدة إلا ببصمتها.
- [ ] **عدم التعديل:** لم يتم نسخ القاعدة المستعادة محل قاعدة المستشفى التشغيلية أو إجراء ترحيل فعلي أو حركة بنك دون موافقة منفصلة.
- [ ] **تجربة الرفض:** اختير أرشيف خاطئ/معدل في اختبار صناعي مستقل وتأكدنا من فشل الاستعادة وعدم ترك بيانات مفكوكة.
- [ ] **فجوة الزمن:** قورن RPO وRTO المقاسان بالحد المعتمد، ووثقت الخطوات التي قد تفقد معاملات بعد توقيت النسخ.
- [ ] **السجل التاريخي:** تظل بوابة V8.0 وافتتاح الأرصدة **BLOCKED** ما لم تقدم أصولها وتطابقات موقعة.
