# معاينة HTTPS محمية بكلمة مرور مستقلة

## النطاق

هذا بديل تجريبي بعد فشل POST عبر بوابة البريد في Quick Tunnel ، مع بقاء حماية مستقلة قبل برنامج رمسيس. جرى اختباره على macOS مع Apache2.4.67 و cloudflared2026.10.7. لا يُعد استضافة دائمة أو إعداد مستشفى إنتاجيًا، ولا يُستخدم لبيانات تشغيل حقيقية.

المسار:

```text
المتصفح → HTTPS من Cloudflare → Apache على 127.0.0.1:8766
          → تحقق Basic Auth من ملف bcrypt خاص
          → تطبيق رمسيس على 127.0.0.1:8765
          → تسجيل دخول التطبيق و Secure/HttpOnly cookie و CSRF
```

الأولى كلمة مرور بوابة المعاينة، والثانية حساب داخل البرنامج. BasicAuth ليست تحققًا بالبريد أو MFA. لا تعتمد على سرية الرابط لحماية الموقع، ولا تجعل التطبيق يستمع على 0.0.0.0 أو تنشر منفذ 8765 مباشرة.

## ملفات الإعداد

- يستخدم قالب [Apache](S12_PASSWORD_GATEWAY_MACOS.conf.example) مجلدًا مؤقتًا خاصًا، وأسماء افتراضية لا تحتوي كلمات مرور.
- على macOS لم يستطع Apache قراءة إعداداته داخل Documents ؛ استُخدم مجلد جديد في`/private/tmp` بصلاحيات 0700 ، وملف bcrypt بصلاحيات 0600. لا تُنقل إليه قاعدة مرضى أو كلمات مرور تشغيلية.
- أنشئ ملف كلمات المرور بواسطة `htpasswd -i -B -c PATH preview`، مع تمرير كلمة مرور عشوائية من stdin ، وحفظها للمستخدم في ملف خاص. لا تمررها في عنوان URL أو تحفظها في Git أو سجلات HTTP.
- عدل تعريف`GATEWAY_ROOT` في القالب إلى المجلد الخاص، ثم نفذ`httpd -t -f CONFIG` قبل التشغيل. لا تعدل إعداد Apache العام أو ملفات System/LaunchAgents.
- شغل التطبيق بإعدادات`RAMSES_ENVIRONMENT=free-preview` و`RAMSES_SECURE_COOKIES=1` وقاعدة الديمو المعزولة فقط. تعطّل أي مرآة Google أو اتصال خارجي مالي. أول تهيئة للديمو تتم عبر`free_preview.init_database` و`seed_preview_demo` كما في المشغل الأصلي.
- شغل Apache باستخدام`httpd -D FOREGROUND -f CONFIG`، مع حد عمال صغير كما بالقالب. وضع`-X` مخصص للتشخيص؛ عند استخدامه هنا تسبب في بطء طلبات ملفات المتصفح المتوازية، ولم يُعتمد للمعاينة النهائية.

## شرط النشر

قبل بدء النفق، يجب نجاح هذه الفحوص على 127.0.0.1:8766:

1. الطلب دون بيانات بوابة أو بكلمة مرور خاطئة يرجع 401 وترويسة`WWW-Authenticate: Basic`.
2. نفس الطلب ببيانات البوابة الصحيحة يصل إلى`/health` ويرجع 200.
3. تسجيل دخول التطبيق يعيد JSON صحيحًا؛ تبقى بيانات Authorization الخاصة بالبوابة خارج التطبيق بعد نجاح التحقق.

بعدها فقط يوجه cloudflared إلى منفذ البوابة 8766. المسار الحالي لا يستخدم`--allowed-mail` لأن البوابة المستقلة هي التي تفرض الحماية، ولا يجوز تشغيل هذا النفق عند توقف البوابة أو إعادة توجيهه إلى التطبيق مباشرة.

بعد صدور عنوان HTTPS: اختبر حظر المجهول، ودخول البوابة، وتسجيل دخول التطبيق، وإعادة التحميل، و`/api/me` بعد الانتظار، والكوكيز Secure/HttpOnly ، من متصفح جديد. اكتفاؤك بفتح HTML أو نجاح health لا يثبت نجاح تسجيل الدخول. هذه الفحوص نجحت في Chrome375/1440 لهذه المرحلة.

## التشغيل والإيقاف

معرّفات عمليات هذه المعاينة وإعداداتها المحلية محفوظة في `private/mobile-gateway/processes.json`. إغلاق المعاينة يكون بإيقاف عملياتها المحددة بعد التحقق من أنها ما زالت نفس البرامج والإعدادات، دون`killall` أو إيقاف أنفاق مشاريع أخرى. المجلدات وكلمات المرور وقواعد البيانات الخاصة لا تُضمّن في الحزمة المنقولة.

إن تغيرت بيئة التشغيل أو أعيد استخراج السورس على جهاز آخر، يعاد إعداد الأسرار والبوابة والتحقق، ولا تُفترض صلاحية رابط قديم. البناء داخل Docker/Linux أو فتح مواقع المستشفى الحقيقية ليس جزءًا من هذا التحقق.
