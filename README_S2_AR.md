# نظام حسابات مستشفى رمسيس — S2 تثبيت دورة الكاشير

**حزمة تطوير واختبار فقط — ليست صالحة للتشغيل على بيانات المستشفى الحقيقية.**

بدأنا من G3N-S1 دون تغيير قاعدة الجداول أو قواعد القيود. أضفنا اختبارًا متصلًا ليوم كامل من أربع ورديات (3 كاشير خارجي + خزنة داخلية)، ومنعنا التوريد المكرر عند إعادة الطلب أو تغيير مفتاحه مع تكرار نفس مرجع الظرف، وربطنا زر التوريد بشاشة الورديات لمستلم العهدة المخوّل.

الاختبار المحاسبي: تحصيل 600 جنيه، مصروف داخلي 50 جنيه، رصيد خزنة نهائي 550 جنيه، مصدر خارجي صفر، قيود متوازنة وإقفال مستقل لكل وردية. الأرقام كلها صناعية.

تجربة الواجهة: مقاسا 375 و1440 بكسل باستخدام Chromium الحقيقي وربط FastAPI داخل العملية، دون الاعتماد على HTTP/TLS الفعلي. تم أيضًا إصلاح مواعيد الورديات التي كانت تظهر `undefined`.

## طريقة فحص المطور

1. افصل أي بيانات أو مفاتيح حقيقية عن بيئة الاختبار. أنشئ بيئة Python من متطلبات السورس طبقًا للـREADME الأصلي.
2. شغّل `python tests/test_s2_cashier_24h_acceptance.py`.
3. شغّل `python tests/test_s2_treasury_retry.py`.
4. في بيئة بها Playwright Chromium، شغّل `python tests/browser_s2_cashier_treasury_ui.py`.
5. راجع `docs/project-autopilot/TEST_REPORT.md` و`PROJECT_STATUS.md` و`ROADMAP.md` قبل أي تشغيل إنتاجي.

لا تنقل سجلات المستشفى الحقيقية إلى البيئة التجريبية، ولا تنشر الحزمة قبل اعتماد الإدارة المالية والمسؤولين الطبيين وتقنية المعلومات، واختبار النسخ الاحتياطي والاستعادة على جهاز مختلف.
