# حسابات مستشفى رمسيس — S8: ثبات هوية الوردية التاريخية

**الحالة: TEST ONLY / غير مُعتمد للتشغيل المالي الحقيقي**

## لماذا هذا الإصلاح؟

كانت شاشة الورديات واليومية تُعيد تسمية وردية قديمة باستخدام آخر جدول كاشير محفوظ، حتى لو لم يبدأ العمل بهذا الجدول إلا غدًا؛ كما قد يظهر كود وردية مخصصة فارغًا في اليومية. هذا خطأ عرض قد يؤدي إلى فهم خاطئ لمستند العهدة عند المراجعة، لكنه لا يعني أن مبالغ الحركات تغيّرت.

## ما الذي تغير؟

- إعادة اسم الوردية `shift_name` من إصدار جدول نقطة التحصيل الذي كان ساريًا في `business_date` من خلال `cashier_ops.historical_shift_name`، مع إبقاء كود `shift` الأصلي بدون تعديل.
- تطبيق نفس المصدر على `GET /api/shifts`, `GET /api/shifts/day-summary`, و `GET /api/shifts/{id}/daily-report`.
- تحديث شاشة الورديات بالمتصفح (كمبيوتر/موبايل/يومية كل وردية/اليومية المجمعة) لاستخدام الاسم التاريخي المُعاد من الخادم، لا اسم الجدول الأحدث.
- الإبقاء على الجداول الجديدة لتكوين **الورديات المستقبلية فقط**؛ الاحتفاظ بكود أي وردية تاريخية غير معروف عند عدم توفر جدولها.
- إصلاح تاريخ تجريبي ثابت في اختبار المتصفح القديم، حتى لا يتعطل عندما يتقدم شهر التشغيل الحالي.

**لا يوجد تعديل في قاعدة البيانات أو الدفاتر أو الصلاحيات أو إجمالي النقدية؛ لم تُنشأ صفحة جديدة.**

## إعادة الاختبار على نسخة تجريبية

```bash
python tests/test_s8_historical_shift_identity.py
python scripts/qa_s8_http.py
python tests/browser_s8_shift_history_offline.py
python tests/browser_shifts_render_offline.py
python tests/test_s2_cashier_24h_acceptance.py
python tests/test_s4_integrated_day.py
python scripts/ci_smoke.py
python scripts/qa_g2t_full.py
```

اختبار S8 ينشئ قاعدة SQLite مؤقتة ونقطة كاشير ذات اسم عربي، يفتح وردية تاريخها اليوم، ثم يعتمد جدولًا يسري غدًا باسم جديد؛ ويقارن اسم الوردية في واجهات القراءة بعد تغيير الجدول. اختبارات المتصفح تعمل محليًا ببيانات صناعية وبدون HTTPS أو اتصال بشبكة المستشفى. `qa_s8_http.py` ينشئ خادم Uvicorn حقيقي عبر loopback، وليس اختبار TLS أو جهاز منفصل.

4. توثيق صاحب السلطة المالية والطبية وIT وتوقيعات الاعتماد، واعتماد سياسة الفروقات ومطابقة 2200 قبل الإقفال.
